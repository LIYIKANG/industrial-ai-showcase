# 明胶配料求解系统

按客户规格从半成品库存中求解配料方案。填上需求量和客户规格单上的指标，系统用混合整数
线性规划（MILP）算出**用哪几批料、各取多少公斤**，使混配后的加权平均命中规格。

- **多项目标** —— 冻力、PH、粘度、水分…… 规格单上写几项就填几项
- **带方向的约束** —— 「冻力 ≥ 210」就是只能高不能低，配低了整批不合格
- **取料偏好** —— 高冻力料稀缺，可以指定保留高端料或保留低端料
- **多单协同** —— 多张订单共享同一批库存同时求解，不会把同一批料重复分给两张单
- **数据看板** —— 接单能力曲线一眼看出这批库存能做什么牌号、最多做多少
- **方案对比** —— 人工贪心 vs 四种优化目标，横向评估成本/冗余/消化/耗时吨
- **历史回溯** —— 用 2025 年真实台账做同条件对照：把一个月里人工实际消耗的全部批次
  汇成料池、重新分配给当月全部订单，投入的料/产出的单/每单吨数三者不变，只换配法

## 快速开始

```bash
cd blending-system
./start.sh
```

浏览器打开 <http://127.0.0.1:8848>

## 三个页面

| 页面 | 作用 |
|---|---|
| **数据看板** | 接单能力曲线、冻力分布、指标余量、等级构成 —— 一屏看清库存能做什么 |

| **参数设定** | 设定混配成品各项指标的上下限，以及求解默认参数；配置落盘持久化 |

## 核心思路

加权平均约束本来是分式的：

```
Σ xᵢ·vᵢⱼ / Σ xᵢ = tⱼ
```

但订单总量 `W` 是给定的，分母 `Σ xᵢ ≡ W` 为常数，于是等价于

```
Σ xᵢ·vᵢⱼ = tⱼ·W          ← 线性
```

所以这是个**线性规划问题，不是搜索问题**。全局最优可以直接求出来，不需要遍历组合或启发式。
再引入 0/1 变量 `yᵢ`（该批是否启用）就能控制批次数与单批最小取用量。

详见 [docs/03-算法说明.md](docs/03-算法说明.md)。

## 已知边界

- **PH 值几乎顶到库存上限**：3878 批里 PH ≥ 6.0 的只有 19 批，中位数 5.68。客户若要 PH 6.0
  的硬指标，靠配料解决不了，需要从工艺端调整。参数设定页会对这类「必然无解」的区间给出提示。
- **求解时限**：多张订单争抢同一冻力段时可能打满时限。此时返回的仍是有效方案，
  通常与跑满全程的结果一致 —— 时间花在「证明最优」而非「找到解」上。
- **单机单用户**：配置存 JSON 文件，无并发写保护。多产线部署需换成数据库，见 [02-架构设计](docs/02-架构设计.md) 的扩展点。

## 人工 vs 算法（2025 历史回溯）

数据源是上级目录的 `blend_orders_2025.parquet` / `blend_components_2025.parquet`
（由 `parse_2025.py` + `enrich_2025.py` 从 `2025(1).xlsx` 解析而来）。

**对照方式**：把同一个月里人工实际消耗掉的全部批次汇成一个料池，重新分配给当月的全部
配料单。投入的料、产出的单、每张单的吨数三者完全不变，只重新决定「哪批料进哪张单」。

由此得到一个贯穿所有指标的恒等式：

```
Σⱼ(实配ⱼ − 要求ⱼ)·Wⱼ ≡ Σᵢ 冻力ᵢ·Aᵢ − Σⱼ 要求ⱼ·Wⱼ = 常数
⇒ 过剩量 − 欠标量 = 常数 ⇒ 少欠一分，就少浪费一分
```

月内总冻力守恒，算法变不出新的冻力，只能把它从不需要的单搬到需要的单上。这也是
结果自校验的手段：人工与算法算出的「过剩−欠标」必须相等（实测 5649.0 vs 5649.1）。

**两档口径**（页面右上角切换）：

| 口径 | 料池 | 用途 |
|---|---|---|
| 全月统筹 | 当月消耗的全部批次 | 理论上限 |
| 严格时序 | 批次须在月初已在库，或人工已在更早日期用过它 | 掐掉算法「预知未来」的优势（当月入库的料占 21.6% 重量）|

**模型**：每月一个 MILP（`scipy.optimize.milp`/HiGHS）。变量 `x[批,单]`；约束为每单拿满
吨数、每批不超发、四项指标下限加松弛；目标主项是不达标吨位最小，次项是相对缺口最小。
252 张单 / 3639 条投料，全年两档合计约 35 秒。

只约束**冻力、粘度、T450、T620** —— 这四项在台账里覆盖率接近 100%。水分覆盖率仅 36%、
二氧化硫 4.5%，作为约束会凭空造数据，因此只在明细里展示、不进模型。

**逐单配方对照**：明细表点任意一行展开，并排列出人工与算法各自抓了哪几批、各多少公斤、
配比多少、该批四项指标是多少，表尾是加权平均与达标判定。只在一侧出现的批号标「换出 / 换入」，
算法只取一批料的一部分时标「整批 / xxx 中取」（剩下的分给了同月别的单）。

首次打开页面会现算（约 20 秒），结果落盘到 `data/backtest.json`。
命令行预生成：`../.venv/bin/python -m app.backtest`
