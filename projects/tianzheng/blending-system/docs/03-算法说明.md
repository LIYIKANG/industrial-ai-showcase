# 03 · 算法说明

## 3.1 问题定义

给定：

- 库存 `n` 批半成品，第 `i` 批的库存量为 `capᵢ` kg，各项指标为 `vᵢⱼ`
- `K` 张订单，第 `k` 单需要 `W_k` kg，目标冻力 `b_k`，容差 `±tol_k`
- 各项指标 `j` 的成品上下限 `[lo_j, hi_j]`

求：每批料分配给每张订单多少公斤，使所有订单的加权平均指标都落进规格。

## 3.2 关键洞察：这是线性规划，不是搜索

加权平均约束的原始形式是分式的：

```
  Σᵢ xᵢ·vᵢⱼ
  ─────────  =  tⱼ
   Σᵢ xᵢ
```

分式约束是非线性的，直接求解很麻烦。但**移项**即可线性化：

```
  Σᵢ xᵢ·(vᵢⱼ − tⱼ)  ≥  0          ← 完全线性
```

这一步不需要假设总量固定，对任意实配总量都精确成立 —— 整批取料下总量只能
落在订单量附近的窗口里（见 3.3b），这个性质是必需的。

这一步是整个系统成立的基础。它意味着：

- 不需要遍历批次组合（3878 批取 3 批就有 96 亿种组合）
- 不需要遗传算法、模拟退火之类的启发式
- 可以直接求**全局最优**，并且知道它是最优的

## 3.3 完整模型

### 决策变量

| 变量 | 类型 | 含义 |
|---|---|---|
| `x[i,k]` | 连续，`[0, capᵢ]` | 第 `i` 批分配给第 `k` 单的公斤数 |
| `y[i,k]` | 0/1 | 第 `i` 批是否被第 `k` 单启用 |
| `t` | 连续，`[0, 1]` | 所有订单冻力偏差的最大归一化值 |

变量只为**候选对**创建（见 3.5 预筛），不是全量 `n × K`。

### 约束

**(A) 订单总量**

```
W_k·(1 − w_tol)  ≤  Σᵢ x[i,k]  ≤  W_k·(1 + w_tol)          ∀k
```

可拆批时 `w_tol = 0`，退化成等式；整批取料时 `w_tol = weight_tol_pct`（默认 5%），
因为凑不出精确值（见 3.3b）。

**(B) 目标指标** —— 每张订单可指定任意多项，且**每项都有方向**

方向对应客户规格单上的符号。冻力写「≥210」就是 `min`：**配低了不合格，配高了可以接受**。

| 方向 | 含义 | 约束（移项形式，记 `Δᵢ = vᵢ − val`） |
|---|---|---|
| `min` | 只能高不能低 | `Σx·Δ ≥ 0` 且 `Σx·Δ ≤ t·tol·W` |
| `max` | 只能低不能高 | `Σx·Δ ≤ 0` 且 `Σx·Δ ≥ −t·tol·W` |
| `both` | 双向 | `\|Σx·Δ\| ≤ t·tol·W` |

达标那一侧（`≥ 0` / `≤ 0`）是移项形式，对任意总量都精确。
`t` 那一侧的右端仍用名义订单量 `W` 近似 —— 精确写法 `t·tol·Σx` 是双线性的，
MILP 处理不了；总量偏差被 (A) 限在 ±`w_tol` 内，所以只影响居中程度，不影响达标判定。

各指标的默认方向按其物理意义设定：冻力、透过率是 `min`（低了不合格）；
水分、灰分、二氧化硫、粘度下降、电导率是 `max`（超标不合格）；PH、勃氏粘度是 `both`。
每张订单可逐项改。

`t ≤ 1` 保证所有目标都不越界；`t` 进目标函数则驱动结果贴近目标值 ——
单边约束下就是贴着那条不能越过的线。

用同一个 `t` 而不是每项一个，是为了让不同量纲的指标可比：偏差先除以自己的容差再比较，
冻力差 2 Bloom（容差 5）和 PH 差 0.08（容差 0.2）都算 40%，优化时同等看待。

**(C) 全局上下限**

```
Σᵢ x[i,k]·(vᵢⱼ − lo_j)  ≥  0        且        Σᵢ x[i,k]·(vᵢⱼ − hi_j)  ≤  0
```

同样是移项形式，理由同 (B)。

同一指标可以同时有目标值和上下限，两者取交集，互不冲突。
客户规格单上写明的项填成目标值，其余只要不超标的项留给上下限。

**(D) 库存不可超发** ← 多订单的关键约束

```
Σ_k x[i,k]  ≤  capᵢ                          ∀i
```

**没有这条，两张订单会各自把同一批料算满**，方案到车间才发现料不够。
这也是「多订单必须同时求解，而不是逐单求解」的根本原因。

**(E)(F) 启用标志与取料粒度** —— 两种模式二选一

整批取料（默认）：

```
x[i,k] = capᵢ · y[i,k]              取了就取满，不留零头
```

可拆批：

```
x[i,k] ≤ capᵢ · y[i,k]              启用才能取料
x[i,k] ≥ min_take · y[i,k]          取了就不能只取一点点
```

`min_take` 默认 20 kg，仅可拆批时有意义。没有它，求解器会给出「从第 3271 批
取 0.34 kg」这种车间无法执行的碎量。详见 3.3b。

**(G) 每单批次数上限**（可选）

```
Σᵢ y[i,k] ≤ max_batches              ∀k
```

### 目标函数

```
minimize    OBJ · 选定目标   +   BIG · Σ y   +   QTY · d   +   PREF · Σ pref·x   +   t
             ↑ ≤ 5000            ↑ 100/批       ↑ ≤ 50       ↑ ≤ 60               ↑ ≤ 1
```

各项严格分层，每层都比下一层重要一个数量级：

1. **用户选定的目标**（料本最低 / 冗余最小 / 最大消化难用料）。默认「批次最少」时该项为 0
2. **批次数最少**。每多一批料就多一次投料、清洗、转运和记录
3. **贴近订单量**。`d ≥ |Σx − W| / W`，仅整批取料时生效（见 3.3b）
4. **取料偏好**。见下节
5. **尽量居中**。在前几项相同的若干解里挑最贴近目标的那个

### 取料偏好：动哪一端的库存

加权平均被订单总量钉死了，所以「配出来多少冻力」是定的；能选的是**用哪一端的料**。

目标 210 既可以用 205+215 这样的中间料凑，也可以用 60+315 这样的两头料凑 ——
后者会啃掉稀缺的高冻力库存（全库存冻力 ≥300 的只有 5 批）。

界线来自参数设定页的「冻力分段界线」（默认 高≥275 / 低≤120），是**库存政策**而不是
订单属性 —— 配 210 的单时 215 的料并不稀缺，真正该保护的是 275 以上的。

| 偏好 | 惩罚项 `pref[i,k]` | 效果 |
|---|---|---|
| `balanced` | 0 | 只管批次数最少 |
| `save_high` 保留高冻力料 | `max(0, bloomᵢ − θ⁺)`，`θ⁺ = max(高界线, 目标)` | 避开高端库存 |
| `save_low` 保留低冻力料 | `max(0, θ⁻ − bloomᵢ)`，`θ⁻ = min(低界线, 目标)` | 避开低端库存 |

界线要和本单目标取合：目标本身已经落在保护区里时（比如目标 290、保护线 275），
那段料非用不可，只能退化成「尽量贴着目标取」。

系数是常数（每批的冻力已知），所以目标函数仍是线性的，不增加求解难度。

实测（目标冻力 ≥290，需求 3000 kg，界线以目标为准）：

| 偏好 | 用料冻力 | 低于目标的取用量 |
|---|---|---|
| 不偏好 | 284.2 ~ 294.8 | 1004 kg |
| 保留高冻力 | 289.0 ~ 290.6 | 1176 kg（但不碰 294+ 的料） |
| 保留低冻力 | 290.4 ~ 290.9 | **0 kg** |

### 偏好什么时候不起作用

**目标落在中间料充足的区间时，三种偏好给出相同方案。** 例如目标 ≥210：
批次数目标本身就把解推向最密集的近目标料（206~214），压根没伸手去够两端，
保护区内取用量本来就是 0，偏好无从发挥。

这是**正确行为**，不是功能失灵。目标越靠近库存两端（如 ≥290），偏好的影响越明显。

### 权重取值的坑（踩过两次）

`BIG` 必须大于 1（`t` 的上界），才能保证「少用一批」绝对优于「更居中」。
但**不能取得太大**：MILP 的收敛判据是相对间隙 `mip_rel_gap × 目标值`。

最初取 `BIG = 1e4`、`mip_rel_gap = 1e-4` 时，绝对间隙 = `1e4 × 1e-4 = 1.0`，
而 `t ∈ [0,1]` —— 整个居中项被间隙吞掉，求解器认为所有解都"一样好"，
于是随手返回一个冻力 205.9（目标 210）的方案。

现取 `BIG = 100`、`mip_rel_gap = 1e-6`，绝对间隙约 `2e-4`，居中项重新生效。

**第二次：取料偏好被归一化稀释。** 偏好惩罚最初除以整个冻力跨度（255.6）归一化，
结果 1 个 Bloom 的偏差只剩 `1/255.6 = 0.004`，被量级为 1 的居中项 `t` 完全压过 ——
`save_high` 和 `save_low` 给出**完全相同**的方案。

改用容差（5）作分母后偏差变成 0.2，量级正常；同时把权重提到 30、对归一化偏差封顶 2.0
（防止极端料的惩罚膨胀到反过来压过批次数），两种偏好才真正分开。

> 教训：MILP 里**次级目标的量级必须自己算清楚**，不能想当然。
> 两次踩坑的表现都是「参数改了没反应」，根因都是次级目标被更大的量级淹没 ——
> 一次淹没在收敛间隙里，一次淹没在错误的归一化分母里。
> 调试方法也一样：把两个方案的目标函数各项分别打印出来对比。

## 3.3b 整批取料

**车间要求：一批料只要用上就必须用完，不留零头。** 拆批会留下要重新化验、
贴标、入库的半桶料，管理成本比省下的那点料钱高。

### 建模：一条等式

```
xᵢ = capᵢ · yᵢ            取了就取满，没有中间状态
```

`yᵢ` 是已有的「该批是否启用」标志，所以只加一条等式就能切换模式，
(B)(C) 两组指标约束**一行都不用改** —— 它们只认 `x`，不管 `x` 是怎么来的。

关掉整批取料时退回 `xᵢ ≤ capᵢ · yᵢ` 加最小取用量约束，即原来的可拆批行为。

### 副作用一：约束必须改写成移项形式

这是**必须先解决的正确性问题**。原来的写法是

```
Σ xᵢ·vᵢ  ≥  目标 · W          W = 名义订单量
```

可拆批时 `Σxᵢ ≡ W`，没问题。但整批取料后总量 `T ≠ W`，上式推出的是

```
avg = Σx·v / T  ≥  目标 · W / T
```

`T > W` 时 `目标·W/T < 目标`，**约束不再保证达标**。改成移项形式即可根治：

```
Σ xᵢ·(vᵢ − 目标)  ≥  0     ⟺     Σx·v / Σx  ≥  目标
```

对任意总量都精确成立，且仍然线性。上下限约束同样改写。

### 副作用二：总量必须放成区间

批重是 63~934 kg 的任意实数，凑出恰好 3000 kg 是**子集和问题**，实际几乎无解。
所以总量约束放成

```
W·(1 − weight_tol_pct)  ≤  Σ xᵢ  ≤  W·(1 + weight_tol_pct)
```

默认 ±5%。

### 副作用三：总量窗口会被当成套利空间

放开区间后，**任何「越少越好」的目标都会一路贴着窗口下沿走**：

| 目标 | 表现 |
|---|---|
| 批次数最少 | 少发就能少开一批 —— 3000 kg 的单只配 2852 kg（−4.9%） |
| 料本最低 | 更狠 —— 4000 kg 的单只配 3800 kg，料本「省」5%，但单位成本 54.0 vs 54.1 **几乎一样**，省的钱全来自少发 200 kg |

第二种尤其危险：它让方案对比的记分卡**失去意义** —— 客户以为算法省了 5%，
其实是少交了 5% 的货。

所以引入归一化总量偏差 `d ≥ |Σx − W| / (W · w_tol)`（即「用掉了多少总量容差」，
范围 [0,1]），权重 `QTY_WEIGHT = 20000`，并把它放在**最高优先级**：

```
贴近订单量 (≤20000)  ≫  选定目标 (≤5000)  ≫  批次数 (100/批)  ≫  居中 t (≤1)
```

交付量是**合同义务，不是可优化项** —— 各目标只能在「量已经配对」的前提下再去优化。
按窗口宽度而非按 W 归一化，这样改容差设置不会让权重量级飘掉。

加上之后（目标 冻力≥210）：

| 需求量 | 加之前 | 加之后 |
|---|---|---|
| 500 kg | 492.2（−1.56%） | 501.6（+0.32%） |
| 1000 kg | 1047.8（+4.78%） | 999.8（−0.02%） |
| 3000 kg | 2852.8（−4.91%） | 2999.8（−0.01%） |
| 8000 kg | 7621.2（−4.74%） | 8000.0（+0.00%） |

方案对比也随之变公平（4000 kg 单，整批取料）：

| 方案 | 批次 | 实配 | 料本 | 单位成本 |
|---|---|---|---|---|
| 批次最少 | 5 | 4000.0 | 216,702 | 54.17 |
| 料本最低 | 5 | 4000.0 | **216,034** | **54.01** |
| 最大消化难用料 | 6 | 4000.0 | 246,151 | 61.54 |

「料本最低」省下的 ¥668 是同样批次数、同样交付量下真实省出来的。

### 小单是硬约束

整批取料下小单可能真的无解 —— 既要重量落进窗口、又要指标落进容差：

| 需求量 | 容差 | 结果 |
|---|---|---|
| 100 kg | ±5% | 无解（窗口 95~105 kg 内没有一批指标合格） |
| 200 kg | ±5% | 无解（冻力须落在 [210,215]，与重量窗口交集为空） |
| 300 kg | ±5% | 303.2 kg，1 批 ✓ |

这类无解不是「料不够」而是「凑不出来」，通用提示帮不上忙。
所以求解失败时会逐单算出总量窗口、约需批次数、单批就能满足全部指标的批次数，
把杠杆指清楚（提高总量容差 / 放宽指标容差 / 加大订单量 / 关闭整批取料）。

## 3.4 可行性预检

在建模之前先挡掉必然无解的情况，直接给出可执行的原因，而不是让用户等求解器跑完再看到一句
`infeasible`。

核心依据：**加权平均永远落在参与批次的极值之间**。

```
min(vᵢⱼ)  ≤  Σ xᵢ·vᵢⱼ / Σ xᵢ  ≤  max(vᵢⱼ)
```

所以只要目标区间与库存的 `[min, max]` 不相交，再怎么配也配不出来。预检项：

| 检查 | 提示 |
|---|---|
| 候选池为空 | 所有批次都因指标缺失或等级不达标被排除 |
| 库存总量 < 订单合计 | 可用 X kg，需要 Y kg |
| 冻力目标 ± 容差 超出库存区间 | 订单「XX」冻力目标 300±3 超出可达区间 [59.8, 315.4] |
| 指标下限 > 库存最大值 | PH 下限 6.5 高于库存最大值 6.09，无法达成 |
| 指标上限 < 库存最小值 | 同理 |

参数设定页也用同一套逻辑做即时提示，用户改上下限时就能看到「必然无解」。

## 3.5 候选预筛

全量 3878 批 × K 单会产生上万个 0/1 变量，求解时间从秒级涨到分钟级。

### 主体：按多目标归一化距离

**每张订单按到各项目标的归一化距离排序，取最近的 N 批**（默认 200）：

```
distᵢ = Σ_j ( (vᵢⱼ − valⱼ) / tolⱼ )²        j 遍历该单的目标指标
```

各项偏差先除以自己的容差再平方求和，量纲才可比。

排序只看目标指标，不看仅有上下限的指标 —— 后者是区间约束而非目标，
单批超标的料完全可能被其他批次拉回区间内（这正是配料的价值所在），
按它们筛选反而会误伤有用的料。

### 补充一：目标两侧都要有料

只取距离最近的 N 批，可能出现**全部偏向目标同一侧**的情况 ——
那样加权平均怎么配都过不去，属于假无解。

所以对每项目标，额外补入「值低于目标」和「值高于目标」各最近的若干批（默认各 8 批），
保证求解器在每个目标维度上都能双向调节。

### 补充二：限制项的「矫正料」

只按冻力筛有一个盲区：**某项限制所需要的矫正料可能全部落在冻力较远的批次里。**

实测案例 —— PH 限制收紧到 `[5.0, 5.2]` 时：

| 集合 | PH ≤ 5.2 的批次数 |
|---|---|
| 全库存 3878 批 | 46 |
| 冻力最接近 210 的 200 批 | **1** |

单靠这 1 批拉不动整体加权平均，求解器报无解 —— 但这是**假无解**，全库存里明明有 46 批可用。

修正：对每项启用的限制，检查近邻集里的达标比例，低于 10% 就补入一批
「本身满足该限制、且冻力尽量接近目标」的料（默认 15 批）。只在需要时补，
避免候选集无谓膨胀。

修复效果：同一请求从「无解」变成 **0.1 秒解出 2 批方案**，冻力精确命中 210.0，PH 5.13。
方案选的是冻力 263.0 和 139.9 两批 —— 单看都离目标很远，混出来正好 210，
这正是之前被筛掉的矫正料。

> 教训：预筛是性能优化手段，但**任何按单一维度做的预筛都会在多维约束下产生假无解**。
> 补充规则必须由约束本身驱动，而不是靠调大 N 去撞运气。

### 补充三：按订单量扩容

预筛出来的候选集必须装得下这张单。曾经出现过「全库存 1928 吨，配 150 吨却报无解」——
无解的其实是那 200 批候选（约 100 吨），不是库存。

现在按需要量往下扩，留 3 倍余量供混配调节（只取刚好够的量意味着几乎没有配比自由度）。

> 教训与「假无解」那条同源：**预筛的每一个维度都可能成为伪约束**。
> 距离维度会漏掉矫正料，容量维度会漏掉总量 —— 凡是预筛，都要问一句
> 「它会不会把本来可行的解筛掉」。

### 补充四：LP 松弛定位（非默认目标时）

前三条补充都是**邻域式**的：先取离目标最近的一批，再往外打补丁。
这套思路对「批次最少」够用，但换成成本、冗余、消化这类目标就系统性失效 ——
**目标函数的取值遍布整个库存，最优解可能落在离目标很远的地方。**

实测：把低冻力料打到 3 折后

| 候选数 | 料本 | 用了低端料 |
|---|---|---|
| 200（默认预筛） | 162,000 | **0 kg** |
| 2000 | 148,737 | 734 kg |
| 全池 3784 | **147,867** | 757 kg |

默认预筛下 `min_cost` **一点低端料都不用**，比全池最优贵 8.7% —— 便宜的 120 料和
把加权平均拉回目标所必需的 300 料，都离目标 210 太远，全被邻域预筛切掉了。

曾先后尝试「注入最便宜的料」「注入最极端的料」等启发式：每加一个目标就要重写一次
注入规则，而且都补不全（注入"最便宜"时，高侧最便宜的是 210 附近的料，真正需要的
275 提拉料反而因为贵被排除）。

**正确解法是 LP 松弛。** 去掉 0/1 变量后问题退化成纯线性规划：

```
minimize  Σ xᵢ · cᵢ            c 是该目标的每公斤系数（成本 / 冗余 / 消化）
s.t.      Σ xᵢ = W
          各项目标与上下限约束（与 MILP 完全相同）
          0 ≤ xᵢ ≤ capᵢ
```

- **全池 3784 批只要 ~24 ms**（没有整数变量，HiGHS 直接单纯形）
- 线性规划的基本解至多有「约束个数」个非零分量 —— 实测**支撑集只有 10 批**，
  正好是成本最优需要的那几批：4 批 120 的便宜料 + 6 批 300 的提拉料
- 把支撑集并入候选集，MILP 再在小集合上精算批次数与最小取用量

LP 的目标值同时是**成本下界**（146,377），可以用来判断 MILP 解离最优还有多远。

代码见 `solver.py` 的 `_lp_support()`。`objective="min_batch"` 时不触发，行为不变。

### 订单间的候选重叠

不同订单的候选集会重叠，这没问题：约束 (D) 保证不会重复分配。

## 3.6 无解时的兜底

若 `t ≤ 1` 无解，系统会放开 `t` 的上界重跑一次，返回「最接近能做到的方案」并明确标注超差项。

比只回一句 `infeasible` 有用得多：用户能直接看到差多少，据此决定是找客户谈放宽容差，
还是补料、换单。

## 3.7 性能实测

测试环境：Apple Silicon，Python 3.12，SciPy 1.18（HiGHS）。

| 场景 | 候选池 | 耗时 | 结果 |
|---|---|---|---|
| 单订单，1 项目标（冻力 210，200 kg） | 3878 | **0.03 s** | 1 批，冻力 210.0 精确命中 |
| 单订单，3 项目标（冻力+PH+粘度，800 kg） | 3784 | **3.7 s** | 2 批，三项全中 |
| 2 单（220/3000kg + 180/2000kg） | 3784 | **3.6 s** | 7 批，全部达标 |
| 3 单（220/180/260） | 3878 | **3.7 s** | 13 批，全部达标 |
| 2 单多目标（3 项 + 2 项） | 3784 | 打满时限 | 4 批，全部达标 |
| 4 单全挤在冻力 300（库存上限附近） | 3878 | 打满时限 | 12 批，全部达标 |

### 打满时限意味着什么

**不意味着方案更差。** 对「2 单多目标」这一行做了对照实验：

| 时限 | 实际耗时 | 结果 |
|---|---|---|
| 5 s | 5.0 s（打满） | 4 批，全部达标 |
| 15 s | 15.0 s（打满） | 4 批，全部达标 |
| 60 s | 27.6 s（收敛） | **4 批，全部达标 —— 同一个解** |

三次得到的是**同一个方案**，60 秒那次只是多花 22 秒证明了「它确实是最优的」。
候选数在 80 / 120 / 200 之间调整也是同样结论。

也就是说：**时间花在「证明」而不是「寻找」上**。默认时限 15 秒，
超时会在结果页提示但不影响方案可用性 —— 延长时限一般不会改变结果。

## 3.8 调优手册

| 现象 | 调整 |
|---|---|
| 求解太慢 | 调小「每单候选批次数」（200 → 100）；调小求解时限 |
| 方案批次太多 | 设「每单最多用几批」；或放宽指标上下限 |
| 解出碎量，车间没法执行 | 调大「单批最小取用量」 |
| 冻力总是贴着容差边界 | 检查 `BIG` 与 `mip_rel_gap` 的关系（见 3.3） |
| 频繁无解 | 看参数设定页的「库存实际范围」列，哪项限制贴着边界就放宽哪项 |
| 想让方案更居中 | 直接调小冻力容差 —— 容差本身就是最直接的居中控制手段 |
