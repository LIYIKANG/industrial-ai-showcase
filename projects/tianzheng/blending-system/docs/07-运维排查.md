# 07 · 运维与故障排查

## 7.1 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.10+（开发与测试用 3.12） |
| 操作系统 | macOS / Linux / Windows（WSL） |
| 内存 | 512 MB 足够（3878 批数据约占 2 MB） |
| 网络 | 仅首次安装依赖时需要 |

依赖见 `requirements.txt`：polars、fastexcel、numpy、scipy、fastapi、uvicorn。

## 7.2 安装与启动

```bash
cd blending-system
./start.sh
```

`start.sh` 会自动检查虚拟环境和依赖，缺什么装什么。

**换端口**

```bash
PORT=9000 ./start.sh
```

**手动启动**（调试用，带热重载）

```bash
../.venv/bin/python -m uvicorn app.main:app --reload --port 8848
```

**后台常驻**

```bash
nohup ./start.sh > blend.log 2>&1 &
tail -f blend.log
```

## 7.3 日常操作

### 更新库存数据

1. 用新数据覆盖 `副本AI 测试模拟数据-20260805(1).xlsx`（保持列结构一致）
2. 浏览器 → 库存数据页 → 点「**重新导入**」
3. 顶部批次数变化即表示成功

不需要重启服务。若换了文件名，改 `app/config.py` 的 `SOURCE_XLSX`。

### 备份

需要备份的只有两样：

- `data/limits.json` —— 参数上下限配置（工艺部门的设定成果）
- 源 Excel

`data/inventory.parquet` 是缓存，删掉会自动重建，不用备份。

### 重置配置

界面上「参数设定 → 恢复默认」，或直接删掉 `data/limits.json` 后重启。

## 7.4 故障排查

### 启动失败

**`ModuleNotFoundError: No module named 'xxx'`**

```bash
../.venv/bin/python -m pip install -r requirements.txt
```

若下载超时（国内网络），换镜像：

```bash
../.venv/bin/python -m pip install -r requirements.txt \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**`Address already in use`** —— 端口被占：

```bash
lsof -nP -iTCP:8848 -sTCP:LISTEN     # 看是谁占了
PORT=9000 ./start.sh                 # 或直接换端口
```

**`FileNotFoundError: 找不到源数据文件`** —— 检查 `config.SOURCE_XLSX` 路径。
注意文件名里的空格和括号要完全一致。

### 页面打不开 / 一片空白

1. 看右上角状态灯。红色 = 后端没响应，先看终端日志
2. 浏览器 F12 → Console 看报错
3. 直接访问 <http://127.0.0.1:8848/api/health> 确认后端是否正常

### 数据不对

**批次数不是 3878**

正常。3878 是当前源文件清洗后的数量。若明显偏离（比如变成 4055），
说明空行剔除没生效 —— 检查 `config.PARAM_KEYS` 是否与源表列名对得上。

**某列全是「—」**

该列在源表里是空的，或列名对不上。启动日志会打印实际列名，对照 `config.PARAMS` 的 `key`。

### 看板打不开 / 图表空白

1. 浏览器 F12 → Console 看报错
2. 直接访问 <http://127.0.0.1:8848/api/dashboard> 确认后端聚合是否正常
3. 图表按容器宽度绘制，窗口极窄时可能画不开 —— 拉宽窗口即可

### 方案对比相关

**几个方案结果完全一样**

正常情况见 [08 §8.4](08-方案对比评估.md)：单一冻力目标 + 线性定价时，料本被目标值钉死，
`min_cost` / `min_batch` / `min_redundancy` 必然重合。加多几项目标指标就会拉开差距。

**选了「最大消化难用料」却消化 0 kg**

检查 `solver.py` 的 `OBJ_WEIGHT`（应为 5000，必须远大于 BIG=100）与 `_lp_support()`
是否正常返回支撑集 —— 这两处任一失效都会让该目标塌缩回「批次最少」，
详见 [08 §8.7](08-方案对比评估.md) 与 [03 §3.5 补充四](03-算法说明.md)。

**「料本最低」和「批次最少」结果一模一样**

先确认定价曲线的形状。凸曲线（高冻力溢价快，明胶的实际形态）下，
集中取料本来就同时是最便宜和批次最少的 —— 这是数学必然，不是故障，
详见 [08 §8.4](08-方案对比评估.md)。

只有便宜料分散在冻力两端时（例如呆滞料被折价）两者才会分开。
若此时仍然重合，检查 `_lp_support()` 是否被跳过：日志里搜 `LP 定位失败`。

**整批取料下小单报无解**

不是料不够，是**凑不出来** —— 既要重量落进总量窗口、又要指标落进容差。
错误信息里会给出该单的总量窗口、约需批次数、以及单批就能满足全部指标的批次数。
四个杠杆按代价从低到高：提高「总量允许偏差 ±%」→ 放宽指标容差 → 加大订单量 →
关闭「整批取料」允许拆批。详见 [03 §3.3b](03-算法说明.md)。

**实配量和需求量差得多**

整批取料下两者必然不等（批重是任意实数，凑不出精确值）。正常偏差应在 ±0.5% 内 ——
`QTY_WEIGHT` 那一项会把结果拉回名义订单量。

若偏差长期贴着容差上/下沿（尤其「料本最低」方案），检查 `solver.py` 的
`QTY_WEIGHT`（应为 20000，**必须大于 OBJ_WEIGHT=5000**）。它一旦被目标函数压过，
求解器就会把总量窗口当套利空间：少发 5% 换来「料本省 5%」的假象，
而单位成本其实没变 —— 记分卡会误导客户。详见 [03 §3.3b](03-算法说明.md)。

**用料单里有批次没被「清空」**

整批取料模式下每批的取用量必须等于库存量。若出现不等，说明 `whole_batch`
没传到求解器 —— 检查请求的 `settings.whole_batch`，或参数设定页的开关状态。

**成本数字看起来不合理**

当前定价是**占位值**。去「方案对比」页的定价曲线区块换成真实价格。

### 求解相关

**一直转圈不出结果**

求解时限默认 15 秒，加上网络往返最多 20 秒左右。超过说明：

- 订单数太多（上限 20）
- 候选批次数设得过大 → 参数设定页调小到 100

**总是提示无解**

按顺序排查：

1. 结果页红色横幅里的 `reason` 已经指明了哪一项 —— 先看它
2. 去参数设定页，看该项的「库存实际范围」列
3. 若上下限与库存范围没有交集 → **必然无解**，只能放宽或补料
4. 若有交集但仍无解 → 多项限制叠加导致。逐项取消勾选定位是哪几项冲突

**方案里有 0.5 kg 这种碎量**

调大「单批最小取用量」。

**冻力总是贴着容差上沿或下沿**

正常情况下不该出现。若出现，检查 `solver.py` 的 `BIG` 与 `mip_rel_gap`
是否被改动过 —— 两者的乘积必须远小于 1，否则居中项失效
（详见 [03-算法说明 §3.3](03-算法说明.md)）。

**结果提示「达到求解时限」**

方案仍然可用。多单争抢同一冻力段时，时间主要花在证明最优而非寻找解上，
实测超时返回的方案与跑满全程的质量一致。

## 7.5 日志

服务端日志输出到终端（或 `nohup` 指定的文件），格式：

```
23:17:42  INFO    blending  已加载库存 3878 批，合计 1927933.6 kg
23:18:03  INFO    uvicorn   127.0.0.1 - "POST /api/blend HTTP/1.1" 200
```

求解异常会打印完整堆栈。关键日志点：

| 日志 | 含义 |
|---|---|
| `已加载库存 N 批` | 数据加载成功 |
| `从缓存加载库存` | 走了 parquet 缓存 |
| `parquet 缓存读取失败，回退到 Excel` | 缓存损坏，已自动恢复，无需干预 |
| `配置文件损坏，已回落到默认值` | `limits.json` 格式错误，设定丢失需重设 |
| `容差内无解，放开容差重试` | 正在计算「最接近方案」 |

## 7.6 安全说明

当前配置为**本机监听**（`127.0.0.1`），只有本机能访问，无鉴权。

若要在局域网内共享，改 `config.HOST = "0.0.0.0"` —— 但请注意：

- 系统**没有任何身份验证**，同网段任何人都能访问和修改参数
- 建议先加反向代理（nginx）做 Basic Auth，或限制来源 IP
- 生产环境部署前应补充用户体系，见 [02-架构设计 §2.6](02-架构设计.md) 扩展点

## 7.7 卸载

删掉 `blending-system` 目录即可。虚拟环境 `../.venv` 若不再他用也可一并删除。
源 Excel 不会被修改。
