# 05 · 使用手册

## 5.1 启动

```bash
cd blending-system
./start.sh
```

浏览器打开 <http://127.0.0.1:8848>。右上角显示绿点和「库存 3,878 批」表示数据就绪。

停止：终端里按 `Ctrl+C`。

---

## 5.2 数据看板

打开系统的默认页面，回答一个问题：**这批库存能做什么单、最多做多少**。

### 接单能力曲线（最该先看的一张）

横轴是客户要求的目标冻力，纵轴是这个牌号最多能配出多少吨。悬停查看任意目标值。

原理：冻力 ≥ 目标的料全部用上会产生**冻力盈余**，这份盈余能带动多少低于目标的料
做压秤，决定了总产量上限。两条红色虚线标出产能腰斩和跌破一成的位置 ——
**这就是接单谈判的实际边界**。

当前库存的形态：

| 目标冻力 | ≥150 | ≥210 | ≥240 | ≥260 | ≥280 | ≥290 |
|---|---|---|---|---|---|---|
| 最大可配 | 1928吨 | 1767吨 | 1258吨 | 784吨 | 233吨 | 53吨 |

260 以上产能开始塌陷，282 以上不足总库存一成。业务上的含义是：
**高牌号订单接单前必须先查这条曲线**，不能凭"库存还有 1900 多吨"就答应。

### 库存冻力分布

按**吨位**而非批数统计 —— 能不能接单取决于有多少料，不是有多少批。
虚线是参数设定页的分段界线。

### 冻力分段构成

低 / 中 / 高三段的吨位占比。高冻力料只占 8.9%，这是"取料偏好"要保护它的原因。

### 各指标相对规格的余量

灰色轨道是规格区间，蓝条是库存 p5~p95 的实际落点，按最紧的排在前面。

余量只算**真正会卡壳的那一侧**：水分、灰分这类"越低越好"的看上限，
透过率这类"越高越好"的看下限。灰分下限写 0 只是形式，报它的下方余量没有意义。
余量低于 10% 会标红。

### 水不溶物等级构成

四个等级的吨位占比。4 级只有 2.4%，默认的"最差可接受 3 级"排除的就是这部分。

## 5.3 库存数据页

进入系统的默认页面。

**顶部四张卡**：库存批次数、总量、冻力范围、冻力中位数。
先看一眼冻力范围 —— 客户目标超出这个范围就一定配不出来。

**库存明细表**

- 点任意列标题排序，再点一次切换升/降序
- 工具栏可按冻力区间、重量下限、水不溶物等级、编号筛选，点「筛选」生效
- 「重新导入」用于源 Excel 更新后刷新数据（见 [07-运维排查](07-运维排查.md)）

**指标分布表**（页面底部）

每项指标的最小 / p5 / 中位 / 均值 / p95 / 最大 / 缺失数。
设定上下限之前建议先看这里 —— 把限制卡在 p5 以下或 p95 以上会让可选料急剧减少。

## 5.4 配料求解页

### 基本流程

1. 填「需求量」，勾选客户规格单上写明的指标并填目标值
2. 点「+ 添加目标」增加订单，一次可提交多张
3. 点「生成配料方案」

### 订单头

| 字段 | 必填 | 说明 |
|---|---|---|
| 单号 / 备注 | 否 | 留空自动编号。多单时建议填客户名，方便对照 |
| 需求量 | **是** | 该单要配多少 kg |
| 取料偏好 | 否 | 见下文 |

### 目标指标

默认只勾选冻力。客户规格单上写了几项就勾几项，每项三个输入：

| 输入 | 说明 |
|---|---|
| **方向** | `≥` 只能高不能低 · `±` 双向 · `≤` 只能低不能高 |
| **目标值** | 规格单上的数 |
| **容差 ±** | 允许偏多少。留空用默认值 |

**方向就是规格单上的那个符号。** 冻力写「≥210」就选 `≥` ——
配成 208 整批不合格，配成 213 客户不会退货。系统按各指标的物理意义预设了方向：

| 默认 `≥`（低了不合格） | 默认 `≤`（超标不合格） | 默认 `±`（两头都不能偏） |
|---|---|---|
| 冻力、透过率450、透过率620 | 水分、灰分、粘度下降、电导率、二氧化硫 | PH值、勃氏粘度 |

容差的含义随方向变：`≥210 ±5` 表示结果落在 **[210, 215]**，不是 [205, 215]。

### 取料偏好

加权平均被需求量钉死了，所以「配出来多少冻力」是定的；能选的是**用哪一端的料**。

目标 210 既可以用 205+215 的中间料凑，也可以用 60+315 的两头料凑 ——
后者会啃掉稀缺的高冻力库存（全库存冻力 ≥300 的只有 5 批）。

| 选项 | 效果 | 什么时候用 |
|---|---|---|
| **不偏好** | 只求批次数最少 | 默认，不在意用哪端 |
| **保留高冻力料** | 用贴近目标的中间料 | 高端料要留给高牌号订单 |
| **保留低冻力料** | 几乎只用目标值以上的料 | 低冻力料后面有低规格订单要用 |

实测（目标冻力 ≥290，需求 3000 kg）：

| 偏好 | 用料冻力 | 低于目标的取用量 |
|---|---|---|
| 不偏好 | 284.2 ~ 294.8 | 1004 kg |
| 保留高冻力 | 289.0 ~ 290.6 | 1176 kg（但不碰 294+ 的料） |
| 保留低冻力 | 290.4 ~ 290.9 | **0 kg** |

底部三个选项是**本次求解临时覆盖**，不会改动全局设置：

- **单批最小取用** —— 避免解出「取 0.3 kg」这种车间没法执行的碎量
- **每单最多用几批** —— 0 表示不限。限制越严越可能无解
- **求解时限** —— 打满时限返回的方案通常依然可用（见下）

### 读结果

**顶部横幅**：绿色=全部达标，红色=存在超差项。同时给出订单数、总批次数、总量、耗时。

**共用批次提示**（黄色横幅）：某批料被多张订单同时取用。总量没超库存，
但车间分料时需注意先后顺序。

**每张订单一个卡片**，左右两栏：

- **左：用料单** —— 用哪几批（`#编号`）、各取多少 kg、占比，以及各批的目标指标值
- **右：规格达成情况** —— 每项指标的实际值 vs 要求
  - 蓝色`目标`标签 = 该单指定的目标项，「要求」列显示规格单写法（`≥ 210`）
  - 灰色`限制`标签 = 参数设定页的全局上下限兜底项
  - 目标项有一条进度条显示用掉了多少容差。绿色安全，黄色接近边界，红色超差

**导出 CSV**：按单导出，带 BOM，Excel 双击直接打开不乱码。可直接作为车间配料单。

### 关于「达到求解时限」提示

看到这条提示不必重算。多张订单争抢同一冻力段时，好解通常几秒内就找到了，
剩下的时间都花在「证明它是最优」上 —— 实测把候选数在 80/120/200 之间调整，
得到的都是同样质量的方案（见 [03-算法说明 §3.7](03-算法说明.md)）。

### 无解怎么办

红色横幅会直接说明原因，常见三类：

| 原因 | 处理 |
|---|---|
| 目标超出库存可达区间 | 只能补料或找客户谈。加权平均永远落在库存极值之间，这是物理约束 |
| 目标与全局上下限冲突 | 例如冻力目标区间和参数设定页的冻力上下限没有交集，改其中一边 |
| 某项指标的上下限超出库存范围 | 去参数设定页看该项的「库存实际范围」，放宽到有交集 |
| 库存总量不足 | 降低需求量，或分批交付 |

## 5.5 参数设定页

### 指标上下限

这里设的是**混配成品**要满足的区间，**不是单批物料的筛选条件**。

这个区别很重要：某批料灰分 0.37 单看超标，但配上另一批灰分 0.05 的料后加权平均是 0.28，
完全合格。按单批筛选会把这批好料白白排除 —— **这正是配料相对于挑料的价值**。

| 列 | 说明 |
|---|---|
| 启用 | 取消勾选则该指标完全不参与约束 |
| 下限 / 上限 | 留空表示不限。只填一边也可以 |
| 库存实际范围 | 当前库存该指标的 [最小, 最大]。**目标超出它就必然无解** |
| 说明 | 自动提示「必然无解」或「接近库存边界，可选料很少」 |

改完点「保存」，下次求解立即生效。「恢复默认」会覆盖当前全部设定。

### 冻力分段界线

定义什么算**高冻力料**、什么算**低冻力料**，供配料页的「取料偏好」使用。

改动界线时下方会实时显示圈住了多少库存（批次 / 吨位 / 占比），并列出冻力分位数 ——
对照着选，不用凭感觉。默认 高≥275（p90）/ 低≤120（p15），
分别圈住 8.9% 和 16.0% 的库存。

设成 0 / 9999 则退化为「以本单目标值为界」。

> **注意**：取料偏好只在「最优解本来就要动用保护区」时才生效。
> 目标 210 这类中间料充足的牌号，求解器天然就用近目标的料，三种偏好结果相同 ——
> 这是正确行为，不是偏好没起作用。目标越靠近库存两端，偏好的影响越明显。

### 求解默认设置

| 设置 | 说明 |
|---|---|
| 冻力默认容差 ± | 配料页每行留空时使用 |
| 单批最小取用量 | 避免碎量。默认 20 kg |
| 每单最多用几批 | 0 = 不限 |
| 每单候选批次数 | 按冻力接近程度预筛。越大解越优但越慢，默认 200 |
| 求解时限 | 默认 15 秒 |
| 可接受的最差水不溶物等级 | 差于该等级的批次直接排除。默认 3 级 |

## 5.6 典型场景

### 场景一：单个客户订单

客户要 500 kg、冻力 210 ± 5 的料。

1. 配料页填：需求量 `500`，冻力勾上、方向 `≥`、目标值 `210`
2. 点「生成配料方案」→ 通常 1~2 批即可达标
3. 导出 CSV 交车间

若客户还写了「水分 ≤ 12%」，把水分也勾上、方向选 `≤`、填 12 即可。

### 场景二：一天多张订单排产

早上收到三个客户的单：220 × 3000kg、180 × 2000kg、260 × 1500kg。

**不要分三次求解** —— 那样三张单会各自把同一批好料算进方案，到车间才发现料不够。

正确做法：三行一次提交。求解器的库存约束 `Σ_k x[i,k] ≤ capᵢ` 从建模上杜绝重复分配，
并在结果页明确列出被多单共用的批次。

### 场景三：客户规格卡得很紧

客户要求 PH 必须 ≥ 6.0。

1. 先去库存页看 PH 的分布：中位数 5.68，p95 = 5.90，最大 6.09
2. 意味着 3878 批里 PH ≥ 6.0 的极少（实际只有 19 批）
3. 参数设定页把 PH 下限设 6.0，说明列会提示「接近库存边界，可选料很少」
4. 求解大概率无解 —— 这不是软件的问题，是**库存里根本没有那么多高 PH 的料**

这种情况需要工艺端调整，或与客户协商放宽。系统的价值在于**5 分钟内就能给出这个结论**，
而不是让老师傅试算半天。

### 场景四：车间嫌批次太多

方案给了 6 批，车间希望不超过 3 批。

1. 把「每单最多用几批」设为 3，重新求解
2. 若无解，说明 3 批凑不出这个规格 —— 要么放宽冻力容差，要么接受更多批次
