# PDF Analyzer AI - 系统设计书

## 1. 系统概要

### 1.1 系统名称
PDF Analyzer AI（PDF智能文档解析系统）

### 1.2 系统目的
利用大语言模型（Claude AI）的自然语言理解和视觉识别能力，自动从PDF文档中抽取结构化信息，并填入Excel模板，实现文档数据的自动化处理。

### 1.3 适用范围
- 不动产租赁合同的信息抽取
- 可通过配置文件扩展至任意PDF文档类型

## 3. 功能模块设计

### 3.1 模块一览

| 模块 | 功能 | 入口函数/文件 |
|------|------|---------------|
| PDF文字提取 | 从文字型PDF中提取文本 | `extract_text_from_pdf_bytes()` |
| PDF图片转换 | 将扫描件PDF转为base64图片 | `pdf_bytes_to_base64_images()` |
| AI智能抽取 | 调用Claude API进行信息抽取 | `process_pdf()` |
| JSON解析 | 容错解析AI返回的JSON | `parse_json_from_model_output()` |
| Excel模板填充 | 将数据写入Excel模板 | `fill_excel_template()` |
| 配置管理 | 加载字段映射配置 | `load_config()` |
| 前端交互 | 文件上传、进度展示、结果下载 | `app.js` |
| 国际化 | 日语/中文界面切换 | `app.js (i18n)` |

### 3.2 PDF解析策略（核心逻辑）

系统采用**双路径策略**自动适配不同类型的PDF：

```
PDF上传
  │
  ▼
尝试用pypdf提取文字
  │
  ├── 提取到文本 ──▶ 【文字模式】
  │                   将全文本发送给Claude
  │                   Prompt要求从文本中抽取字段
  │
  └── 文本为空 ────▶ 【扫描件模式】
                     用PyMuPDF将每页转为JPEG图片
                     Base64编码后发送给Claude视觉API
                     Prompt要求从图片中识别并抽取字段
```

**设计理由**:
- 文字模式成本更低、速度更快（仅传输文本）
- 扫描件模式利用Claude的多模态视觉能力，无需额外OCR服务
- 自动检测，用户无需关心PDF类型

### 3.3 AI Prompt设计

#### 文字模式Prompt
```
System: 你是一个严谨的结构化信息抽取助手，只输出JSON。
User:   你是一个文档信息抽取助手。
        给你一份不固定格式的PDF全文文本，请根据语义理解，从中抽取指定字段。
        只返回一个JSON对象...
        需要抽取的字段定义如下：[字段列表]
        下面是PDF提取出的全部文本：[PDF文本]
```

#### 扫描件模式Prompt
```
System: 你是一个严谨的结构化信息抽取助手，只输出JSON。
User:   [图片1, 图片2, ..., 图片N]
        以上是一份PDF文档的所有页面图片。
        请仔细识别图片中的所有文字内容，然后从中抽取指定字段。
        只返回一个JSON对象...
        需要抽取的字段定义如下：[字段列表]
```

**关键参数**:
- `model`: claude-sonnet-4-6（平衡性能和成本）
- `max_tokens`: 4096
- `temperature`: 0.1（低温度保证输出稳定性）

### 3.4 JSON容错解析

AI返回的文本可能包含额外字符，系统实现了多层容错：

```
原始文本
  │
  ├── 1. 去除 ```json ``` 代码块包裹
  │
  ├── 2. 尝试直接 json.loads()
  │
  └── 3. 失败则正则提取第一个 { 到最后一个 } 之间的内容
        再次 json.loads()
```

### 3.5 Excel模板填充

```
加载Excel模板 (openpyxl)
  │
  ▼
遍历配置中的fields
  │
  对每个字段：
  ├── 获取AI抽取的值（data[field.id]）
  ├── 定位目标单元格（field.cell）
  ├── 检测是否为合并单元格
  │   ├── 是 ──▶ 写入合并区域左上角
  │   └── 否 ──▶ 直接写入
  │
  ▼
保存到临时文件并返回
```

## 4. 前端设计

### 4.1 页面状态机

前端采用三状态单页应用设计：

```
[STATE 1: 上传] ──点击解析──▶ [STATE 2: 处理中] ──完成──▶ [STATE 3: 结果]
      ▲                                                       │
      └───────────────── 点击"新文件" ──────────────────────────┘
```

| 状态 | 面板ID | 功能 |
|------|--------|------|
| 上传 | `#state-upload` | 文件拖拽/选择、历史记录 |
| 处理中 | `#state-processing` | 进度条、统计卡片、实时日志 |
| 完成 | `#state-complete` | 结果统计、文件信息、下载按钮 |

### 4.2 国际化设计 (i18n)

- 支持语言: 日语(ja)、中文(zh)
- 实现方式: HTML元素使用 `data-i18n` 属性标记，JS中维护翻译字典
- 持久化: 语言选择保存在 `localStorage`
- 切换机制: 导航栏语言切换按钮，实时更新所有文本

### 4.3 进度模拟

由于后端为单次请求，前端通过定时器模拟解析进度：

```
0%  ── 上传开始
5%  ── 文件上传中
15% ── PDF结构解析中
25% ── 文字层提取中
35% ── AI识别中
35-85% ── 每1.5秒随机增加1-5%（等待AI响应）
90% ── Excel生成中
100% ── 完成
```

### 4.4 响应式设计

| 断点 | 适配 |
|------|------|
| > 768px | 桌面端完整布局 |
| <= 768px | 统计卡片单列、上传按钮全宽 |
| <= 480px | 隐藏导航标题、缩小字体 |

## 5. 数据流设计

### 5.1 完整请求处理流程

```
1. 用户选择PDF文件
2. 前端通过FormData POST到 /api/process
3. 后端读取PDF字节内容
4. 重新加载配置文件（支持热更新）
5. 尝试用pypdf提取文字
6. 根据文字提取结果选择处理路径：
   a. 有文字 → 构建文本模式Prompt
   b. 无文字 → PDF转图片 → 构建视觉模式Prompt
7. 调用Claude API进行智能抽取
8. 解析AI返回的JSON结果
9. 加载Excel模板，将数据填入对应单元格
10. 保存Excel到临时目录
11. 返回FileResponse（Excel文件 + 统计信息响应头）
12. 前端接收blob，展示结果，提供下载
```

### 5.2 数据格式

**AI输入（字段定义）**:
```json
[
  {"id": "customer_name", "label": "賃借人の氏名（借主名前）"},
  {"id": "rent", "label": "賃料（数字のみ、円単位）"}
]
```

**AI输出（抽取结果）**:
```json
{
  "customer_name": "田中太郎",
  "rent": "85000",
  "property_name": "サンハイツ新宿",
  ...
}
```

## 6. 安全设计

### 6.1 API密钥管理
- 使用 `.env` 文件存储敏感信息
- `.env` 已加入 `.gitignore`，不会提交到版本控制
- 启动时检查 `CLAUDE_API_KEY` 是否存在，缺失则报错退出

### 6.2 文件安全
- 仅接受 `.pdf` 后缀文件
- 上传文件不持久化存储，处理完即释放
- 生成的Excel保存在系统临时目录，由OS自动清理

### 6.3 CORS配置
- 当前配置: `allow_origins=["*"]`（开发阶段）
- 生产建议: 限制为实际部署域名

### 6.4 输入验证
- 文件类型校验（后缀检查）
- 空文件检测
- JSON解析容错（防止AI输出异常导致崩溃）

## 7. 扩展性设计

### 7.1 支持新文档类型
只需创建新的 `field_mapping.json` 配置：
1. 准备对应的Excel模板
2. 定义需要抽取的字段（id, label, cell）
3. 更新配置文件路径

### 7.2 配置热加载
每次API请求重新读取 `field_mapping.json`，无需重启服务即可更新字段配置。

### 7.3 多模型支持
AI调用部分可通过修改 `model` 参数切换不同Claude模型：
- `claude-sonnet-4-6`: 平衡性能（当前使用）
- `claude-opus-4-6`: 最高精度
- `claude-haiku-4-5-20251001`: 最快速度

## 8. 性能考虑

| 环节 | 优化措施 |
|------|----------|
| 图片传输 | JPEG质量60%，最大边1600px，减小体积 |
| PDF渲染 | 使用1.5倍矩阵，平衡清晰度和内存 |
| AI调用 | temperature=0.1，减少随机性，提高一致性 |
| 配置加载 | 热加载但仅在请求时读取，不轮询 |
| 前端 | 无框架依赖，加载速度快 |

---

## 9. 已知限制

1. **单文件处理**: 当前仅支持单次上传一个PDF
2. **无批量功能**: 不支持批量PDF处理
3. **无结果编辑**: 无法在前端修改AI抽取的结果后再下载
4. **无用户认证**: 当前为单用户本地使用模式
5. **无处理历史持久化**: 服务端不保存处理记录
6. **Excel模板固定**: 每次请求使用同一模板，不支持动态选择
