# PDF Analyzer AI - 开发说明书

## 1. 项目概述

**项目名称**: PDF Analyzer AI（PDF智能文档解析系统）

**项目目标**: 通过AI技术自动解析PDF文档（支持文字PDF和扫描件），智能抽取关键字段信息，并自动填入指定的Excel模板中，大幅减少人工录入工作量。

**当前应用场景**: 日本不动产行业 - 自动解析租赁合同PDF，提取租借人信息、物件信息、费用明细等字段，填入「重要事項説明書」Excel模板。

---

## 2. 技术栈

| 组件 | 技术 | 版本/说明 |
|------|------|-----------|
| 后端框架 | FastAPI | Python异步Web框架 |
| AI引擎 | Claude API (Anthropic) | claude-sonnet-4-6 模型 |
| PDF文字提取 | pypdf | 提取文字层PDF的文本 |
| PDF图片转换 | PyMuPDF (fitz) | 将扫描件PDF转为图片 |
| 图像处理 | Pillow | 图片缩放、对比度增强、锐化处理 |
| Excel处理 | openpyxl | 读写xlsx模板 |
| 前端 | 原生HTML/CSS/JS | 无框架依赖 |
| 运行服务器 | Uvicorn (开发) / Gunicorn (生产) | ASGI服务器 |
| **认证** | **JWT (python-jose)** | **Access Token + Refresh Token 双令牌体系** |
| **密码加密** | **passlib + bcrypt** | **bcrypt哈希，固定3.2.2版本** |
| **数据库** | **SQLAlchemy + SQLite/PostgreSQL** | **本地SQLite，生产可切换PostgreSQL** |

## 6. 认证系统

### 6.1 架构概述

```
浏览器
 │
 ├─ GET  /login              → 登录页面（无需认证）
 ├─ POST /auth/login         → 验证凭据 → 返回 access_token（JSON）
 │                             + 设置 refresh_token（HttpOnly Cookie）
 ├─ GET  /                   → 主应用（JS检查token，无token跳转/login）
 ├─ POST /api/process        → 需要 Bearer Token（get_current_user依赖）
 ├─ POST /auth/refresh       → 用Cookie中的refresh_token换取新access_token
 └─ POST /auth/logout        → 将refresh_token加入黑名单，清除Cookie
```

### 6.2 Token机制

| 令牌 | 存储位置 | 有效期 | 用途 |
|------|---------|--------|------|
| Access Token | 浏览器 sessionStorage | 15分钟 | 每次API请求携带 |
| Refresh Token | HttpOnly Cookie | 7天 | 自动刷新Access Token |

- **sessionStorage**：关闭标签页自动清除，安全性高于localStorage
- **HttpOnly Cookie**：JS无法读取，防止XSS窃取
- **Refresh Token Rotation**：每次刷新旧Token立即加入黑名单，防止重放攻击

### 6.3 角色权限

| 角色 | 主功能（PDF解析） | 用户管理后台 `/admin` |
|------|:---:|:---:|
| `admin` | ✅ | ✅ |
| `operator` | ✅ | ❌（403）|

### 6.4 登录保护机制

- **失败锁定**：同一账号连续失败5次 → 锁定15分钟
- **审计日志**：每次登录/登出/失败记录到 `audit_logs` 表（时间、IP、用户名）
- **密码强度**：8字符以上 + 大写 + 小写 + 数字（新建/修改时校验）
- **首次强制修改**：管理员新建的用户首次登录后必须修改密码

### 6.5 前端认证集成（static/auth.js）

```javascript
// auth.js 在 index.html 最先加载，全局包装 window.fetch
// 所有 fetch() 调用自动携带 Authorization: Bearer <token>
// 收到 401 时自动尝试刷新Token，刷新失败则跳转登录页

Auth.requireAuth()    // 页面加载时检查，未登录跳转/login
Auth.logout()         // 登出（通知服务器 + 清除token + 跳转）
Auth.fetchMe()        // 获取当前用户信息（用于显示姓名/角色）
```

## 8. API接口

### 8.1 页面路由（无需Token）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/login` | 登录页面 |
| GET | `/change-password` | 修改密码页面 |
| GET | `/admin` | 用户管理后台（页面本身无保护，JS检查admin角色）|

### 8.2 认证API（无需Token）

#### 登录
```
POST /auth/login
Content-Type: application/json
{"username": "admin", "password": "Admin1234!"}
```
**响应**:
```json
{
  "access_token": "eyJ...",
  "token_type": "bearer",
  "expires_in": 900,
  "must_change_password": false
}
```
同时在Cookie中设置 `refresh_token`（HttpOnly）。

#### 刷新Token
```
POST /auth/refresh
（Cookie自动携带 refresh_token）
```

### 8.3 认证API（需要Bearer Token）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/logout` | 登出，refresh_token加入黑名单 |
| GET | `/auth/me` | 获取当前用户信息 |
| POST | `/auth/change-password` | 修改密码 |

### 8.4 管理员API（需要admin角色）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/users` | 用户列表 |
| POST | `/api/admin/users` | 创建用户 |
| PUT | `/api/admin/users/{id}` | 更新用户（角色/状态/密码）|
| DELETE | `/api/admin/users/{id}` | 禁用用户 |
| GET | `/api/admin/audit-logs` | 审计日志（最近500条）|

### 8.5 主功能API（需要Bearer Token）

#### PDF/图片处理
```
POST /api/process
Authorization: Bearer <access_token>
Content-Type: multipart/form-data
Body: pdf_files=<文件1>, pdf_files=<文件2>, ...
```

**成功响应**:
```json
{
  "file_id": "12345_abcd",
  "filename": "filled_xxx.xlsx",
  "fields_filled": 32,
  "fields_total": 38,
  "page_count": 4,
  "extracted": [
    {
      "id": "property_name",
      "label": "物件名称",
      "cell": "C31",
      "value": "グランドパレス",
      "filled": true,
      "source": "contract.pdf",
      "note": ""
    }
  ]
}
```

#### 文件下载
```
GET /api/download/{file_id}?filename=filled_xxx.xlsx
Authorization: Bearer <access_token>
```

#### 手动修正后重新生成
```
POST /api/regenerate
Authorization: Bearer <access_token>
Content-Type: application/json
{"fields": [{"id": "property_name", "value": "グランドパレス"}], "filename": "filled.xlsx"}
```

## 11. 常见问题

### Q: Windows 运行 init_db.py 报 UnicodeEncodeError
A: 使用 `python -X utf8 scripts/init_db.py`，强制UTF-8模式。

### Q: pip install 报 cp932 解码错误
A: `requirements.txt` 中不能包含日文/中文注释，只能使用ASCII字符。

### Q: passlib bcrypt 报 ValueError: password cannot be longer than 72 bytes
A: `bcrypt>=4.0` 与 passlib 不兼容。固定版本 `bcrypt==3.2.2` 可解决。

### Q: 上传PDF后报错"无法将PDF转换为图片"
A: 确保已安装 `pymupdf` 包，且PDF文件未损坏。

### Q: AI返回的JSON解析失败
A: 系统内置多种JSON解析容错机制。如仍失败，检查PDF内容是否清晰可读。

### Q: 如何添加新的PDF文档类型支持？
A: 只需修改 `config/field_mapping.json`，添加字段定义和Excel单元格映射，无需改代码。

## 12. 注意事项

1. **API密钥安全**: `.env` 已加入 `.gitignore`，切勿提交到版本控制
2. **JWT_SECRET安全**: 生产环境使用独立的密钥，与开发环境不同
3. **INIT_ADMIN_PASSWORD**: 数据库初始化完成后，建议从 `.env` 删除此项
4. **生产环境文件权限**: `chmod 600 .env.production`（仅自己可读）
5. **生产CORS设置**: 修改 `CORS_ORIGINS` 为实际域名，不使用 `*`
6. **bcrypt版本**: 固定在 3.2.2，升级前需验证与passlib的兼容性
7. **Token黑名单清理**: 定期执行 `service.cleanup_blacklist(db)` 清理过期记录
8. **SQLite并发**: 小团队（<10人）SQLite足够；并发量大时切换PostgreSQL（只需改 `DATABASE_URL`）
