# 客户信息排查与后续脱敏清单

本次完成的是功能命名、客户入口收敛和数据排查，**没有完成业务数据脱敏**。运行页面、Docker 镜像和源码包仍可能包含原业务数据。以下清单供项目负责人内部使用，不放在客户网页中。

## 本次已处理

- 以 Agent 功能命名总览、导航、独立指引页和操作页；不再以客户公司名分组。
- 客户资料入口只列两个指定演示样例。后端按固定文件标识提供下载，原方案、报价附件、Excel 和会议录像的旧下载链接返回 404。
- 保留原始文件，不覆盖五个源文件夹及官网项目；没有删除现有 Docker 数据卷。
- 客户页面的运行状态只读，不再提供日志阅读和服务重启管理按钮。故障窗口仍可请求重试启动。
- 密钥、真实环境配置、日志和当前会话数据库继续排除在源码归档规则之外；注意求解器种子数据库是明确保留的例外。

## 建议实施顺序

1. 建立独立的合成演示数据集及字段映射规则，客户代号、SKU、批号、订单号在各应用中保持一致。
2. 替换 PDF、商品消息、库存、历史回溯和求解器种子；使用独立数据卷，不覆盖原业务数据。
3. 重新执行每个 Agent 的示例、修改参数、失败提示和导出测试，核对导出的 Excel、Word、CSV 也无原客户信息。
4. 构建专用对外镜像，检查源码包、镜像层、挂载卷、浏览器草稿和日志。审核通过后，再作为可分发的客户演示版本。

本机当前端口只绑定 127.0.0.1。本轮没有实现公网登录、跨客户数据隔离或完整匿名化发布。
